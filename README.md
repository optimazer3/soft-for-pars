# Optimizer · Сводка по клиентам

Локальный сайт, который заходит на сайты Оптимайзера ваших клиентов (`https://<клиент>.optmzr.ru`)
под их логинами и собирает показатели с «Главной»: «План продаж на очки» с прогнозом и факт, план и % выполнения
по всем 67 метрикам — итогом по клиенту и по каждому салону. Сбор идёт автоматически по расписанию (по умолчанию 09:00, 14:00, 19:00)
или по кнопке.

## Запуск

Нужен Python 3.10+ ([python.org](https://www.python.org/downloads/), при установке на Windows отметьте «Add Python to PATH»).

**Windows:** дважды кликните `start.bat`.
**macOS / Linux:** `./start.sh`

Первый запуск сам создаст окружение `.venv`, поставит зависимости и создаст файл `.env` —
вставьте в него строку подключения к Supabase (см. ниже) и запустите `start.bat` ещё раз.
Затем откроется браузер на http://127.0.0.1:8000.

### Подключение к Supabase

1. Supabase → ваш проект → кнопка **Connect** → **Connection string** → вариант **Session pooler**.
2. Скопируйте строку вида
   `postgresql://postgres.<id проекта>:[YOUR-PASSWORD]@aws-0-<регион>.pooler.supabase.com:5432/postgres`,
   замените `[YOUR-PASSWORD]` на пароль базы (если забыт — Database → Settings → Reset database password).
3. Вставьте её в `.env` после `DATABASE_URL=`. Файл `.env` в git не попадает.

Таблицы создаются автоматически при первом запуске — в Supabase ничего настраивать не нужно.

### Переход со старой версии (SQLite)

Если программа уже работала на ноутбуке, после настройки `.env` один раз выполните

```
start.bat --import-sqlite
```

Клиенты, настройки и свежие снимки перенесутся из `data/optimizer.db` в Supabase (повторный запуск ничего
не дублирует). Старый файл не удаляется. Пока окно программы открыто, сбор идёт по расписанию; если ноутбук был выключен
в момент запуска по расписанию, сбор выполнится сразу после старта программы.

Параметры: `start.bat --port 8080` — другой порт, `--no-browser` — не открывать браузер.

## Установка на сервер

Ubuntu 22.04/24.04, домен направлен A-записью на IP сервера. Код в `/opt/svodka`, файл `.env` рядом, затем:

```
sudo bash deploy/install.sh ваш-домен.ru
```

Скрипт ставит Python-окружение, Caddy (HTTPS от Let's Encrypt), автозапуск через systemd (`svodka.service`),
часовой пояс Москвы и брандмауэр (открыты 22, 80, 443). Обновление: `sudo bash deploy/update.sh`.
Логи: `journalctl -u svodka -f`. Перезапуск: `sudo systemctl restart svodka`.

## Вход

Сайт закрыт паролем. Пользователи хранятся в таблице `app.users` (логин и пароль открытым текстом) —
их можно добавлять, менять и удалять прямо в Supabase (Table Editor → схема `app` → `users`).

- Пока в таблице нет ни одного пользователя, работает встроенная учётка `admin` с мастер-паролем владельца
  (в коде лежит только его хэш). После первого входа она записывается в `app.users`.
- Сессия — подписанная cookie (HttpOnly). С галочкой «Запомнить меня» вход не истекает: cookie продлевается
  при каждом посещении. Без галочки — до закрытия браузера (не дольше 12 часов).
  Смена пароля (в «Настройках» или прямо в базе) или удаление пользователя сразу завершают его сессии.
- Защита от подбора: после 5 неверных попыток вход с этого адреса блокируется на 30 с, дальше блокировка растёт до 30 мин.
- Забыли пароль — `start.bat --reset-login` (или `python run.py --reset-login`) удалит пользователей,
  и снова заработает `admin` с исходным мастер-паролем.

## Что внутри

| Вкладка | Что делает |
|---|---|
| **Дашборд** | Все клиенты с 10 ключевыми показателями (как карточки на «Главной» Оптимайзера). Режимы «Карточки» и «Таблица» с сортировкой, поиск. «Подробнее» — все показатели клиента по группам, переключение по салонам и таблица сравнения салонов. |
| **Клиенты** | Список клиентов: статус последнего сбора и ошибка, вкл/выкл авто-сбора, сбор вручную, редактирование, удаление. |
| **Добавить** | Адрес сайта, логин, пароль. Кнопка «Проверить» входит на сайт и показывает найденные салоны. |
| **Настройки** | Время авто-сбора и параметры бережного режима (лимиты нагрузки на сайты). |

## Как устроен сбор

Оптимайзер — это Next.js-сайт с JSON API под `/summary_api`. Программа работает с ним напрямую, без браузера:

1. `POST /summary_api/api/auth/login` `{"email": логин, "password": пароль}` → токен
2. `GET /summary_api/api/default-period` → текущий период (`2026-11`)
3. `GET /summary_api/api/branches` → салоны
4. `GET /summary_api/api/kpi?period=…[&branch_guids=…]` → показатели: итог и по каждому салону
5. `GET /summary_api/api/monthly-progress?period=…[&branch_guids=…]` → «План продаж на очки»:
   `execution_percent`, `progress_percent` (доля прошедшего месяца), `forecast_percent`, `plan_amount`, `fact_amount`.
   Сумма под прогнозом считается как на сайте: `(forecast_percent / 100 − 1) × plan_amount`.

6. `GET /summary_api/api/activity/weekly?weeks=2&granularity=week` → «Мониторинг активности»: минуты в системе
   по каждому пользователю за прошлую и текущую неделю (на дашборде — сумма по команде в часах).
7. `GET /summary_api/api/tasks/weekly[?week_start=…]` → «Задачи»: выполнено / всего за текущую и прошлую неделю.
8. `GET /summary_api/api/badges` и `/api/badge-assignments?current_only=true` → «Аудиобейджи»: выдано / всего.

Клиент с N салонами — это 10 + 2N запросов (с 3 салонами — 16).

На дашборде по каждому клиенту: выполнение плана продаж, прогноз на конец месяца, итого сумма заказов,
заказы ВТЛ, активность (часы), задачи прошлой и текущей недели, аудиобейджи и дата актуальности данных.

## Бережный режим (защита сайтов от нагрузки)

Все клиенты — поддомены `optmzr.ru` и, скорее всего, живут на одном сервере, поэтому лимиты действуют
и на каждый сайт, и на весь домен сразу (`app/throttle.py`, `app/collector.py`):

| Защита | По умолчанию |
|---|---|
| К одному сайту — строго один запрос за раз и пауза между запросами | 0,7 с |
| Одновременных запросов на весь домен | 2 |
| Общий лимит частоты на домен | не больше ~3 запросов/с |
| Повторы только при временных ошибках (сеть, 429/502/503/504), с растущей паузой и случайным разбросом | 3 попытки, паузы ~3 и ~10 с |
| Ответ 429 или заголовок `Retry-After` — пауза для всего домена | до 2 мин |
| Предохранитель: 2 клиента подряд с ошибками сервера → пауза; 4 подряд → остальные клиенты домена пропускаются до следующего сбора | пауза 60 с |
| Клиента, успешно собранного недавно, не собираем повторно (и по кнопке, и в «Обновить всех») | 10 мин |
| Только чтение: программа не вызывает никаких изменяющих данных запросов | — |

Первые три параметра и паузу между обновлениями можно менять во вкладке «Настройки» — там же показана
оценка времени сбора. Цена бережности — время: один клиент собирается ~20–30 с, 100 клиентов — ~15–20 минут,
для сбора 3 раза в день это некритично.

## Данные

База — Postgres в Supabase, схема `app`:

| Таблица | Что хранит | Сколько |
|---|---|---|
| `clients` | клиенты: сайт, логин, пароль (открытым текстом), статус последнего сбора | постоянно |
| `users` | пользователи сайта: логин и пароль (открытым текстом) | постоянно |
| `settings` | настройки | постоянно |
| `snapshots` | собранные данные: один снимок на клиента в день | 7 дней (меняется в «Настройках», 1–30), последний снимок клиента — всегда |

При 100 клиентах база занимает единицы-десятки мегабайт — лимит бесплатного тарифа (500 МБ) не грозит.

**Безопасность.** Схема `app` не публикуется через REST API Supabase, на всех таблицах включён RLS без
разрешающих правил, а права ролей `anon`/`authenticated` отозваны — прочитать таблицы может только эта
программа по строке подключения.

**Пароли клиентов и пользователей хранятся открытым текстом** (решение владельца): их видит любой, у кого
есть доступ к проекту Supabase или строка подключения из `.env`. Включите двухфакторную защиту на аккаунте
Supabase и не передавайте `.env`.

Локальная папка `data/` (в git не попадает):

- `data/session.key` — ключ подписи сессий входа (если удалить — все просто войдут заново);
- `data/secret.key` — нужен только для разового перевода паролей, зашифрованных прошлыми версиями,
  в открытый вид (происходит автоматически при запуске).

## Структура

```
app/
  main.py        API (FastAPI) и раздача фронтенда
  optimizer.py   клиент API Оптимайзера
  collector.py   сбор по всем клиентам, прогресс, предохранитель, пауза между обновлениями
  throttle.py    ограничение частоты запросов к сайтам
  scheduler.py   расписание
  auth.py        вход: пользователи из app.users, подписанные сессии, защита от подбора
  db.py          Postgres/Supabase: таблицы, миграции, очистка старых снимков
  sqlite_import.py  перенос данных из старой SQLite-базы
  env.py         чтение .env
  crypto.py      расшифровка паролей от прошлых версий (разовая миграция)
static/          фронтенд без сборки: index.html, css/, js/ (views/ — вкладки), fonts/ (Inter, лицензия OFL)
run.py           запуск сервера
```
